# H1 Exam Guide — Leaving Certificate Computer Science (2023–2026)

## The paper

| Section | Marks | Format |
|---|---|---|
| A — Short answers | 54 | 12 questions × 6 marks; answer any **nine** |
| B — Long questions | 76 | 3 questions × 38 marks; answer any **two** |
| C — Programming | 80 | Two tasks (50 + 30, or 60 + 20); answer **both** |
| **Total** | **210** | |

Section A gives choice, so weaker topics can be avoided — but only nine of twelve, so three can be dropped, not six. Section B choice is narrower: two of three long questions, and each one mixes several chapters. Section C is compulsory and is the single largest block of marks.

## How marks are actually awarded

The schemes use holistic scales, not point-by-point marking:

- **A-scales:** 0 or full marks (correct / no substantial merit).
- **B/C/D-scales:** descriptors such as *very good explanation — clear understanding demonstrated* (full), *fair explanation — limited understanding* (about half), *response with some merit* (low).
- Many questions split the marks: **1 mark for naming** a component, example or principle, then **2–3 marks for the explanation**.
- "No marks for stating yes/no" — a judgement must be justified.
- Where two answers mean the same thing, only the better one counts; repeating a point earns nothing.

**Practical rule:** a definition alone rarely gets full marks. The full-mark answer is *name → explain → apply to the scenario*.

| Command word | What earns marks |
|---|---|
| Identify / Name / List | 1 mark per correct item, no explanation needed |
| Describe | 2 marks fair, 3 marks very good, with detail |
| Explain | 2–3 marks: state the point, then say why it happens |
| Compare / Distinguish | Marks for each side, usually 3–6 total |
| Discuss / Evaluate | 3 marks per developed point, both sides, then a judgement |
| Calculate / Convert | Show the working; a correct answer alone may lose method marks |
| Justify | A reason linked to the scenario, not a restatement |

## Verdict on the chapter notes (before this revision)

The 14 chapter notes covered the book's content well, but on the evidence of the schemes they were **not sufficient for H1**:

1. **Content gaps.** Several examined topics were missing or too thin: TCP/IP layers, OS functions, cache vs RAM, virtual memory, cloud storage trade-offs, Turing machines and ARPANET, complexity notation, quicksort details, SDLC roles, functional/non-functional requirements, information systems, modular design, universal design principles, wireframes, validation vs verification, database use cases, emerging technologies, narrow/AGI/generative AI, computer vision, bias mitigation.
2. **No exam-technique layer.** The notes explained topics but did not say how each is questioned, what the mark tariff is, or how to structure a full-mark answer. The schemes reward *explanation* and *application*, not recall.
3. **Section C is untouched.** 80 marks of programming cannot be revised from notes; it needs practice at writing, testing and debugging code under time.
4. **Weighting was flat.** The notes gave every chapter similar space, while the exam concentrates marks in algorithms, systems, AI, ethics, software development and programming.

Each chapter now ends with a **How it's examined** section: the actual question stems, the marks available, and the answer shape the scheme rewards.

## What an H1 answer looks like

A 3-mark explanation is not three sentences of definition. It is:

> **Point** — what the thing is or does.
> **Because** — the mechanism or reason.
> **Example** — applied to the scenario in the question.

For a 6-mark discussion, give **two developed points**, ideally one for and one against, each with a consequence. For "discuss" questions the scheme repeatedly awards 3 marks per developed argument, capped at two per side.

## Study plan that matches the paper

1. **Section A (54).** Learn the predictable six-mark items: number conversion, logic gates/Boolean, data types, trace-the-loop, CPU/memory, OS, networks, embedded systems, universal design.
2. **Section B (76).** Prepare five or six long-question themes rather than fourteen chapters: systems, algorithms/programming, AI/ethics, software development/requirements, modelling, databases.
3. **Section C (80).** Practise full programs with input validation, loops, lists, functions and output formatting; then practise reading unfamiliar code and tracing it.
4. **Answer technique.** Convert every topic into: definition, example, two advantages, two disadvantages, one scenario application. That covers most 3-mark and 6-mark prompts.
5. **Timing.** The Sections A and B session is 90 minutes: aim for about 40 minutes on Section A and 45 on Section B, leaving 5 to check. Section C is a separate 60-minute session.

## Caution

The schemes state that structure and detail may change from year to year. This guide describes the 2023–2026 papers; use it to prioritise, not to predict exact questions.
