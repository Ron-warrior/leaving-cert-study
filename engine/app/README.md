# Web app

This is the Astro frontend for both subject packs. It owns the notes, banks and
practice screens and reads the shared registry in `../shared/`.

## Stack

- Astro, static output
- TypeScript
- `marked` for the existing Markdown notes
- the shared design system in `src/styles/base.css`
- a shared subject/note manifest in `../shared/subjects.json`

## Scope of this slice

- all-subject index
- both subject home pages
- all 31 chapter pages, statically generated, with a heading outline and reading-progress line
- persisted focus-reading mode for chapters
- a lazy static search index across notes, questions, listening questions and transcripts, oral and lab items
- a continue-reading link, a seven-day study strip and a browser-local progress summary on each subject home
- compact progress and resume lines on the all-subjects cards
- `/progress/` export, restore, a month calendar and a daily note for the
  browser-local `gk2-*` state
- a chapter rail on note pages that lists every chapter and keeps the current
  chapter highlighted
- dark/light and persisted focus-reading preferences
- print-friendly chapter view
- self-marking question bank with filters and saved progress
- timed mock exam with a persisted clock and locked marking schemes
- listening papers with audio, year switching, bilingual transcripts, playback
  speed and a 15-second replay
- static oral trainer with roleplays, model answers and conversation prompts
- Section C lab with starter files, sample output, solutions and schemes
- runnable chapter demos with lazy Python, HTML and JavaScript execution
- a search screen at `/search/` backed by a build-time `/search-index.json`
  (about 440 KB, 151 KB gzipped, fetched only when the search page opens); the query and filters
  are kept in the URL, so reloading and Back preserve the search. Press `/` on the
  search page to focus the field

All subject screens are generated by this app.

## Routes

| Route | Screen |
| --- | --- |
| `/` | subject index, including local progress on each subject card |
| `/cs/`, `/spanish/` | subject homes, practice grid, progress and study strip |
| `/cs/notes/<slug>/`, `/spanish/notes/<slug>/` | static chapter pages, outline, focus mode, demos |
| `/cs/questions/`, `/spanish/questions/` | self-marking question banks |
| `/cs/mock/`, `/spanish/mock/` | persisted timed mocks |
| `/spanish/listening/` | audio papers, transcripts and playback controls |
| `/spanish/oral/` | roleplays and conversation bank |
| `/cs/section-c/` | Section C lab with runnable Python |
| `/search/` | lazy full-text search with URL-held filters |
| `/progress/` | export, restore, study-day calendar and daily note |
| `/404.html` | custom not-found page |

## Commands

```sh
npm install
npm run dev -- --host 0.0.0.0 --port 3000
npm run check
npm run build
npm run check:links
```

The app reads the subject registry in `../shared/`, the per-subject data in
`../../subjects/cs/content/` and `../../subjects/spanish/content/`, and the Markdown notes in
`../../subjects/cs/notes/` and `../../subjects/spanish/notes/` at build time. `public/audio`
symlinks to `../../subjects/spanish/audio`, so the static build ships the same three
listening MP3s. The shared registry is the contract for the future native client. Python execution downloads Pyodide from jsDelivr on first use; HTML and
JavaScript demos run in sandboxed iframes. No code or progress is sent to a
server.

## Browser state

The interactive screens keep UI-local state in versioned `gk2-*` keys:

- `gk2-bank-<subject>` — bank year, topic and ticked rubric points,
- `gk2-mock-<subject>` — mock year, deadline, status and self-marks,
- `gk2-listening-<subject>` — selected listening paper,
- `gk2-resume-<subject>` — last opened chapter, used by the subject-home
  continue link,
- `gk2-activity-<subject>` — ISO dates on which a chapter or practice screen was
  opened, used for the seven-day strip,
- `gk2-reflection` — a date-keyed map of short study notes,
- `gk-web-focus` — whether focus-reading mode is on.

The `/progress/` page can export these keys as one versioned JSON file and
restore a previous copy. It never uploads them; the file is a local backup.

A cross-platform progress schema belongs in `../shared/` before native work
starts.

The search index is generated at build time from the Markdown notes and the
shared JSON. It is not hand-edited and is not a content contract; the source
material still lives in `../../subjects/cs/notes/`, `../../subjects/spanish/notes/` and
`../shared/`.
